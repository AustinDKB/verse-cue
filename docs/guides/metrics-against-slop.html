Core teaching

Thesis — read twice

Cyclomatic complexity ≈ how many paths to test.

Cognitive complexity ≈ how hard this function is to read (nesting + flow breaks). It does not punish calling helpers. It often rewards extracting functions. That is why LLMs emit slop that still looks “simple.”

Size / token / file caps stop monster files; they cause file explosion if used alone.

Call-graph / import-graph metrics catch slop between functions: fan-in-1 wrappers, depth ladders, ΔE/ΔV explosions, cycles.

A function can be healthy while the module or service is stinky. That is the central demonstration. We repeat it with numbers.

flowchart TB
  LLM[LLM or human] --> Extract[Extract helpers]
  Extract --> LocalGreen[Local metrics green]
  LocalGreen --> Blind[Misses between-function slop]
  Blind --> Stinky[Stinky service]
  GraphCheck[Graph and diff metrics] --> Catch[Catch ladders]
  Catch --> Balanced[Balanced design]

 LLM → extract helpers → local metrics GREEN
                      → misses graph slop → STINKY SERVICE
 Graph checks → catch ladders → BALANCED DESIGN

Notice: extraction is free for cognitive complexity. Graph cost is not free.

Section 1

Slop and the helper-reward trap

Slop is code that passes local complexity caps but is still hard to understand as a system: helper farms, call ladders, fake layers, one-use wrappers, unused types.

flowchart LR
  Fat[One fat function] -->|extract| Many[Many tiny helpers]
  Many --> CogDrop[Cognitive drops]
  CogDrop --> GatePass[Local gate passes]
  GatePass --> Smell[Fan-in 1 and depth up]

Notice: the local gate trained the wrong behavior.

DEFINITION

Slop = locally green, systemically red. The smell lives in edges and depth, not in one function’s nesting.

SLOP SIGNATURE

Private function, body ≤ 4 statements, fan-in = 1, verb-of-a-verb name (ensure_items). Depth from public entry ≥ 4.

DO THIS

Keep extraction when fan-in ≥ 2 or the name is durable domain language. Otherwise inline.

Section 3 · Family

Control-flow metrics

They count branches and nesting inside one function. They cannot see wrappers next door.

3.1 Cyclomatic complexity (McCabe)

DEFINITION

Cyclomatic complexity ≈ how many independent paths to test. Simplified: \(V(G)=E-N+2\). Practical: start 1; +1 per decision arm (tool-specific).

Good at: test-path budget. Cannot see: helpers; whether a flat match is readable.

3.2 Cognitive complexity (Sonar-style)

DEFINITION

Cognitive complexity ≈ read cost: nesting + flow breaks. Method calls are free. Nesting costs. Match/switch often cheap. Recursion is not free.

EventCost
if / for / while / except+1 + nesting
match / switchOften cheap vs nested ifs
Function callsFree
RecursionCounts

Classic contrast

ShapeCyclomaticCognitive
Flat match / long elif / sequential guardsHighRelatively low
Deeply nested ifsSimilarMuch higher

F1 — Nested ifs vs early returns

Before

def can_ship(order, stock, user):
    if order is not None:
        if user.is_active:
            if stock.available(order.sku) >= order.qty:
                if not order.blocked:

    return False

After

def can_ship(order, stock, user):
    if order is None: return False
    if not user.is_active: return False
    if stock.available(order.sku) < order.qty: return False
    if order.blocked: return False
    return True

Section 4 · Family

Size and token budgets

Size bounds human and LLM edit context. It does not measure design quality.

DEFINITION

LLM-edit budget ≈ how much of a file you can change while still holding surrounding context. Practical band: 300–600 lines / ~3k–6k tokens. Rough: ≈4 chars/token; ~100 lines ≈ 500–1000 tokens.

BudgetLinesTokens
Comfortable300–600~3k–6k
Warn~250~2.5k
Fail start-here>400–500>4k
SLOP SIGNATURE

Size cap without fan-in rule → 40 files of 30 lines.

Section 8

Architecture / slop-shape checks

  • One-use helper: FI1 + tiny + private → inline
  • Call-depth from public entry ≤ 3
  • Max new files / types / abstracts per PR
  • Forbidden ceremony: *Factory, *Manager, Base*, Protocol with one impl
  • Dead code / isolates
  • Tests that only mock private helpers
  • Duplication gate and forced-generic gate

  F[OrderFacade] --> A[A]
  F --> B[B]
  F --> C[C]

Star façade — often ceremony when leaves are FI1.

  P[place_order] --> V[validate_cart]
  P --> R[reserve_stock]
  P --> C2[charge]
  P --> W[write_order]

Small clique of domain verbs — usually balanced.

Section 11 · Tutorial

Threshold Lab

A method, not magic numbers.

  1. Measure 3–5 real PRs or Shopapi S1/S2.
  2. Mark merge/reject by human taste first.
  3. Set limits just tight enough to reject S1 and accept S2.
  4. Warn-only for 2 weeks.
  5. Allowlist generated, migrations, lockfiles, large match tables.
  6. Revisit when a limit forces worse designs.
flowchart TB
  Taste[Human taste] --> Draft[Draft thresholds]
  Draft --> Warn[Warn-only 2 weeks]
  Warn --> Tune[Tighten or loosen]
  Tune --> Fail[Fail gate]
  Fail --> Revisit[Revisit if design worsens]

Notice: taste first, numbers second.

THRESHOLD LAB · Worked

S1reject68

Arrive at: fail depth > 3; fail new private FI1 with body ≤ 4 statements. Rejects S1, accepts S2, allows place_order cognitive = 6.

Section 12

Putting gates in CI

  1. Index HEAD.
  2. Symbols in changed files.
  3. callers / callees / impact --depth 3.
  4. Rules: FI1 tiny private → fail; depth > 3 → fail; new cycles → fail.
  5. affected tests on behavior change.
  6. Warn vs fail rollout.
  7. Pair with Ruff / complexipy / radon — do not replace them.

Section 13 · 90 seconds

Review checklist

  1. Name the workflow in one sentence?
  2. Depth from entry ≤ 3?
  3. New private FI1 wrappers?
  4. Flat match? Allow high cyclo.
  5. New Factory/Manager/single Protocol?
  6. Behavior change → which tests move?
  7. Cognitive rose on real fn while ladder died? Good.
  8. File split: cohesive or confetti?

Section 14

Agent / LLM prompt snippet

Before extracting helpers, check fan-in. Do not add private functions with
fan-in 1 and body ≤ 4 statements. Keep call depth from the public entry ≤ 3.
Prefer raising cognitive complexity on the public workflow over a ladder of
wrappers. Do not add Protocol/ABC/Factory/Manager for a single implementation.
Flat match/elif tables may have high cyclomatic complexity; do not split them
into one-line functions. Pair local complexity caps with call-graph checks on
the PR. Tests must exercise the public API, not only mocks of private helpers.
