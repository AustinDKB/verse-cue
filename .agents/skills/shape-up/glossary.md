# Glossary

- **Appetite** — The time worth spending on a project, rather than an estimate of unlimited work. (Ch 3)
- **Baseline** — What customers do without the thing being built. (Ch 3, Ch 14)
- **Bet** — A one-cycle commitment to a project with uninterrupted time and an expectation to finish. (Ch 8)
- **Betting table** — A cool-down meeting where stakeholders choose the next cycle's bets. (Ch 8)
- **Big Batch** — One project that occupies a team for a whole six-week cycle. (Ch 3, Ch 8)
- **Breadboard** — A UI concept that defines Places, Affordances, and Connection lines without visual styling. (Ch 4)
- **Building track** — The cycle work that teams build after shaping and betting. (Ch 2)
- **Chowder** — A small list for loose tasks that fit no scope. More than three to five items signals a missing scope. (Ch 12)
- **Circuit breaker** — The default rule that stops a project that misses its cycle instead of extending it. (Ch 8, Ch 14)
- **Cleanup mode** — The final new-product phase with no normal shaping or team boundaries, used to prepare for launch. (Ch 9)
- **Cool-down** — A two-week period between cycles for recovery, bugs, experiments, and betting. (Ch 8)
- **Cycle** — A fixed work period. Shape Up uses six weeks as its standard cycle. (Ch 1, Ch 8)
- **De-risk** — Improve the odds of shipping by removing rabbit holes before a bet. (Ch 5)
- **Discovered tasks** — Tasks found after the team starts real work. (Ch 10, Ch 11)
- **Downhill** — Work with no meaningful unknowns left and a known execution path. (Ch 13, Ch 14)
- **Fat marker sketch** — A low-fidelity visual sketch made with a thick line to limit detail. (Ch 4, Ch 6)
- **Grab-bag** — A broad project label with unrelated work and no clear definition of done. (Ch 3, Ch 12)
- **Hill Chart** — A diagram that shows scope status from unknown, through known, to done. (Ch 13, Ch 17)
- **Iceberg** — Work where front-end or back-end complexity greatly exceeds the other side. (Ch 12)
- **Imagined tasks** — Tasks the team expects before it does real work. (Ch 10, Ch 11)
- **Layer cake** — Work with visible UI surface area and thin, evenly distributed back-end work. (Ch 12)
- **Level of abstraction** — The detail included or omitted when describing a problem or solution. (Ch 2, Ch 4)
- **Must-haves** — Tasks required before a scope counts as done. (Ch 14)
- **Nice-to-haves** — Optional tasks marked with `~` and cut when time is short. (Ch 12, Ch 14)
- **No Gos** — Functionality or use cases intentionally excluded from a pitch. (Ch 6)
- **Pitch** — A document with the Problem, Appetite, Solution, Rabbit holes, and No-gos for a potential bet. (Ch 6)
- **Production mode** — The new-product phase after core architecture settles and formal Shape Up cycles apply. (Ch 9)
- **Rabbit hole** — An unknown, complex, or open-ended part that can multiply the appetite. (Ch 5)
- **R&D mode** — The early new-product phase where senior people spike core ideas and architecture. (Ch 9)
- **Raw ideas** — Requests expressed in words that have not received an appetite, solution, or boundary. (Ch 3, Ch 15)
- **Scope** — An integrated project part that can be built and finished independently. (Ch 12)
- **Scope hammering** — Repeatedly questioning design, implementation, and use cases to fit the fixed time box. (Ch 14)
- **Shape** — Make an abstract project idea concrete by defining key solution elements before betting. (Ch 2)
- **Shaping track** — The private work that prepares possible future bets. (Ch 2)
- **Six-week cycle** — The standard time horizon, long enough for meaningful work and short enough for a real deadline. (Ch 1, Ch 8)
- **Small Batch** — Several one- or two-week projects that one team ships within a six-week cycle. (Ch 3, Ch 8)
- **Time horizon** — The longest period in which a team can feel the deadline from the beginning. Shape Up uses six weeks. (Ch 8)
- **Uphill** — Work that still has unknowns or unsolved problems. (Ch 13)
- **Vertical slice** — One integrated piece of design and code that a person can use and evaluate. (Ch 11)
