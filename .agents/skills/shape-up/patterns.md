# Patterns

## Shape Before Bet
**When to use**: A raw idea may consume a fixed cycle.
**How**: Set the appetite, narrow the problem, find the elements, remove rabbit holes, and write the pitch.
**Trade-offs**: Up-front design time delays a possible start, but it reduces fat-tailed delivery risk.

## Fixed Time, Variable Scope
**When to use**: A project has a firm cycle or batch appetite.
**How**: Set time first, then simplify the solution and cut optional work until it fits.
**Trade-offs**: The result excludes some use cases, but it ships with stronger focus.

## Breadboarding
**When to use**: The key risk concerns flow, topology, or interaction.
**How**: Draw Places, Affordances, and Connection lines with words. Play the use case end to end.
**Trade-offs**: It omits visual form, but it exposes behavior quickly and preserves design room.

## Fat Marker Sketching
**When to use**: A visual arrangement carries the main idea.
**How**: Use a thick marker or large digital pen. Add only the strokes needed to discuss the concept.
**Trade-offs**: A sketch may bias layout, but low fidelity limits premature commitment.

## Rabbit-Hole Patching
**When to use**: An edge case threatens the appetite.
**How**: Keep the core value, choose a simple compromise, and record the patch in the pitch.
**Trade-offs**: The compromise may look messy, but it cuts a large risk tail.

## Pitching
**When to use**: A shaped concept needs a resource decision.
**How**: State Problem, Appetite, Solution, Rabbit holes, and No Gos. Post it for asynchronous review.
**Trade-offs**: The pitch takes preparation, but it makes the betting conversation shorter and clearer.

## Betting Table
**When to use**: Cool-down begins and the next cycle needs work.
**How**: Review a few current or deliberately revived pitches, capacity, timing, and people. Place only one-cycle bets.
**Trade-offs**: Passed ideas need advocacy to return, but the company avoids a central backlog.

## Uninterrupted Bet
**When to use**: A team receives a cycle commitment.
**How**: Protect the team from unrelated requests. Wait for the next cycle unless a true crisis occurs.
**Trade-offs**: New issues wait, but the team keeps momentum and the bet remains meaningful.

## Circuit Breaker
**When to use**: A project does not finish within its appetite.
**How**: Stop by default. Re-shape the problem or solution before requesting another bet.
**Trade-offs**: A valuable project may pause, but the company avoids runaway investment.

## Start in the Middle
**When to use**: A new project has many possible starting points.
**How**: Choose a piece that is core, small, and novel. Integrate UI and code in a few days.
**Trade-offs**: Setup remains stubbed, but the team tests the highest-value uncertainty early.

## Scope Mapping
**When to use**: Discovered tasks begin to reveal project structure.
**How**: Factor tasks into independent scopes. Use one to-do list per scope and rename or split lists as needed.
**Trade-offs**: The map changes during week one, but it gives the project accurate language.

## Hill Charting
**When to use**: Task counts cannot show uncertainty.
**How**: Place each scope from uphill unknown to downhill known to done. Save positions over time.
**Trade-offs**: It needs team judgment, but it lets managers see motion without status meetings.

## Scope Hammering
**When to use**: New tasks or edge cases appear near a fixed deadline.
**How**: Compare each item with the baseline. Mark must-haves and prefix optional items with `~`.
**Trade-offs**: The product is selective rather than complete, but quality stays high on core use cases.

## QA for the Edges
**When to use**: The team owns basic quality and needs late edge-case review.
**How**: Let QA find issues near the end. Treat findings as nice-to-haves, then elevate severe items into the affected scope.
**Trade-offs**: QA is not a gate, but the team must own core tests and behavior.

## Product Modes
**When to use**: A new product changes from theory to launch preparation.
**How**: Use R&D mode to spike, production mode to build formal cycles, and cleanup mode to fix and cut before launch.
**Trade-offs**: Expectations change by mode, but each bet remains one cycle.

## Incremental Adoption
**When to use**: The whole organization cannot change at once.
**How**: Start with one protected six-week experiment, better shaping, or longer cycles.
**Trade-offs**: The first version is incomplete, but a shipped result builds credibility.
