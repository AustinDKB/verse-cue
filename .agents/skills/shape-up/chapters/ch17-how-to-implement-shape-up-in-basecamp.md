# Chapter 17: How to Implement Shape Up in Basecamp

## Core Idea
Basecamp maps each Shape Up artifact to one shared place. A small shaping team owns pitches, each cycle project holds one bet, and each scope gets a to-do list and Hill Chart dot.

## Frameworks Introduced
- **Basecamp Team for shaping**: Use a small Product Strategy team for shapers, trusted pitch reviewers, and betting-table stakeholders.
  - When to use: Use it for private shaping and pitch discussion.
  - How: Post pitches as Messages, use a Pitch category, and use the Campfire chat room for coordination.
- **Basecamp Project for a cycle project**: Use one project for each bet.
  - When to use: Use it after the betting table assigns a project.
  - How: Name it with the cycle and project, add the designer and programmers, and post the pitch or a restatement as the kick-off message.
- **To-Do Lists for scopes**: Represent each discovered scope with one list.
  - When to use: Use it after the team gets oriented and begins discovering tasks.
  - How: Add design and programming tasks to the matching scope list, then create or revise lists as the map changes.
- **Track scopes on the Hill Chart**: Link each scope list to a Hill Chart dot.
  - When to use: Use it when the team needs visible progress and uncertainty.
  - How: Choose “Track this on the Hill Chart,” update dots from unknown to known to done, add annotations, and inspect update history.

## Key Concepts
- **Product Strategy**: The Basecamp Team used for shaping.
- **Pitch category**: A Message category that makes pitches easy to find.
- **Cycle project**: A Basecamp Project that contains one cycle bet.
- **Scope list**: A To-Do List representing one integrated project part.
- **Hill Chart history**: Saved positions that show how work moves over time.

## Mental Models
- Think of Basecamp as a **single project surface** for messages, chat, to-dos, and progress.
- Use one **scope list per territory** so the Hill Chart and task details share names.
- Treat the kick-off message as the durable hand-off from shaping to building.

## Anti-patterns
- **Scattered tools**: Separate places hide the pitch, tasks, discussion, and progress from one another.
- **Role-based lists**: A designer list and programmer list do not show integrated scope status.
- **Hill Chart without history**: A current dot without prior updates hides motion and stalls.
- **Large shaping group**: Too many people slow the private work and weaken the betting table.

## Worked Example
For an Autopay bet, the Product Strategy Team stores the pitch as a Message. The betting table announces the project, and the cycle project receives the designer and programmers plus the kick-off message. After orientation, the team creates scope lists such as “Start Autopay” and “ACH Option.” Each list contains design and programming tasks. The team tracks each list on the Hill Chart and adds an annotation when a scope reaches a new state.

## Key Takeaways
1. Keep shaping private in a small Product Strategy Team.
2. Create one Basecamp Project per cycle project.
3. Map each scope to one To-Do List.
4. Track each scope on the Hill Chart.
5. Save progress updates so managers can see movement without asking for status.
