# Chapter 20: Glossary

## Core Idea
The glossary gives Shape Up a precise working language. The distinctions matter because they guide decisions about time, risk, scope, uncertainty, and responsibility.

## Frameworks Introduced
- **Appetite versus estimate**: Appetite chooses time before design. Estimate predicts time after design.
  - When to use: Use appetite for shaping and estimates only when a local task needs a rough planning aid.
- **Imagined versus discovered tasks**: Imagined tasks come from thinking about the pitch. Discovered tasks appear during real work.
  - When to use: Use discovered tasks to update the project map.
- **Uphill versus downhill**: Uphill work still contains unknowns. Downhill work has a known path to execution.
  - When to use: Use this distinction on the Hill Chart and when considering an extension.
- **R&D, production, and cleanup mode**: New products change how teams shape, build, and judge shipping.
  - When to use: Choose the mode that matches the product's confidence and launch stage.
- **Big Batch versus Small Batch**: One project can fill a cycle, or several one- to two-week projects can share it.
  - When to use: Match the batch to the team's capacity and project size.

## Key Concepts
- **Shape**: Make an abstract project idea concrete by defining key solution elements before betting.
- **Appetite**: The time worth spending on a project.
- **Bet**: One cycle of protected team commitment with an expectation to finish.
- **Pitch**: A shaped project write-up for the betting table.
- **Rabbit hole**: An unknown, complex, or open-ended part that is unsafe to bet.
- **Scope**: A project part that can finish independently.
- **Hill Chart**: A diagram from unknown to known to done.
- **Scope hammering**: Forceful questioning that cuts work to fit the time box.

## Mental Models
- Use precise terms as **decision handles**, not as labels for ceremony.
- Think of the glossary's pairs as boundaries: appetite/estimate, raw/shaped, imagined/discovered, uphill/downhill.
- Treat a term's chapter reference as a path to the reasoning behind its definition.

## Anti-patterns
- **Term blending**: Calling an estimate an appetite removes the creative constraint.
- **Status without uncertainty**: Calling every incomplete task “uphill” hides whether the approach is known.
- **Scope without anatomy**: A generic list name prevents independent completion.
- **Mode confusion**: Expecting R&D to ship or cleanup to follow normal shaping creates the wrong pressure.

## Worked Example
A Dot Grid project starts as a raw idea, receives a six-week appetite, and becomes a shaped pitch. The team discovers scopes while building. A novel interaction moves uphill until the team validates it, then downhill as execution proceeds. Optional work receives `~`, and a finished project deploys within the cycle. Each term describes a different decision in the same flow.

## Key Takeaways
1. Use **appetite** for the project time box.
2. Use **scope** for an independently finishable project part.
3. Use **uphill** for unresolved work and **downhill** for executable work.
4. Use **rabbit hole** to name risk that needs shaping.
5. Use the glossary with the chapter files for full reasoning.
