# Chapter 76: Name Hook

## Core Idea
Choose an application name that people can remember, not one that tries to describe every function. An ultradescriptive name often becomes generic and forgettable. A short, catchy name gives the product a distinct hook and makes it easier for people to recall and discuss.

The naming process should stay small and decisive. Do not let a focus group, committee, or exact domain requirement turn a simple choice into a long project. A close domain name can work when the preferred address is unavailable.

## Frameworks Introduced
- **Name Hook — Jason Fried, David Heinemeier Hansson, and Matthew Linderman**: Use a short, catchy, memorable name instead of a generic description of the tool’s purpose.
  - **When to use**: Use it when naming a new application or replacing a forgettable working name.
  - **How**: Prefer a distinct name that people can recall. Avoid excessive committee review. Choose a name, then run with it.
- **Easy Does It — David Pogue**: Make the product name welcoming and easy to describe, use, buy, and sell instead of using language that makes people feel excluded by technology.
  - **When to use**: Use it when a name risks sounding like high-tech club language.
  - **How**: Use clear, approachable words. Keep the name memorable without forcing it to become a literal feature description.
- **Flexible Domain — Jason Fried, David Heinemeier Hansson, and Matthew Linderman**: Treat the exact domain as helpful but not essential.
  - **When to use**: Use it when a preferred domain is unavailable.
  - **How**: Add a small creative variation, such as extra letters or a related phrase, and keep the product name intact.

## Key Concepts
- **Name hook**: A memorable product name that gives people an easy recall point.
- **Ultradescriptive name**: A name that tries to state the product’s complete purpose.
- **Generic name**: A common name that does not distinguish the application.
- **Memorable name**: A name that people can recall and repeat.
- **Committee naming**: A group process that can make naming slow and cautious.
- **High-tech club**: The feeling that technical language excludes ordinary customers.
- **Domain name**: The web address associated with the product.
- **Creative variation**: A small change that makes a close domain available.

## Mental Models
- **Memory over catalog**: A name should create recall before it tries to list functions.
- **Name as doorway**: An approachable name lowers the first barrier to describing and trying the product.
- **Decisive small team**: A focused group can choose a name faster than a committee can reach a safe compromise.
- **Near-match domain**: A close web address can serve the product without controlling the naming decision.

## Anti-patterns
- **Generic descriptor**: A name such as “Project Management Center” blends into its category and is hard to remember.
- **Committee-ized naming**: Too many opinions produce a cautious name without a strong hook.
- **Domain perfectionism**: Rejecting a good name because its exact domain is unavailable delays the product.
- **Technical exclusion**: Jargon can make customers feel that the product is reserved for engineers.
- **Literal overload**: Packing every function into the name makes it long and forgettable.

## Worked Example
The authors compare **Basecamp** with “Project Management Center” and “ProjectExpress.” Basecamp does not describe every function, but it is shorter and easier to remember. They compare **Writeboard** with “CollaborEdit” for the same reason. If the desired domain is unavailable, a team can use a close variation such as `backpackit.com` or `campfirenow.com` rather than abandon a memorable product name.

## Key Takeaways
1. Prefer a short, catchy, memorable name over a generic feature description.
2. Keep the naming group small and decisive.
3. Use approachable words that do not exclude customers.
4. Do not let an unavailable exact domain stop a good name.
5. Run with the selected name instead of reopening the decision repeatedly.
