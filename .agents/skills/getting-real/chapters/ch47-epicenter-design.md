# Chapter 47: Epicenter Design

## Core Idea
Start each page with the one element the page cannot live without. Complete that core unit first, then add the next most important element, and leave navigation, decoration, and other extras for later.

## Frameworks Introduced
- **Epicenter design — Jason Fried, David Heinemeier Hansson, and Matthew Linderman**: Design outward from the page’s true essence.
  - **When to use**: Use it when a screen contains a core content unit plus navigation, sidebars, footers, colors, logos, or other supporting parts.
  - **How**: Identify what makes the page that page. Design and complete it first. Add the second and third critical elements in order of importance.
- **Essentials first, extras second — Jason Fried, David Heinemeier Hansson, and Matthew Linderman**: Protect the page’s purpose from secondary material.
  - **When to use**: Use it when a frame or marketing content may take space from the main function.
  - **How**: Delay extremities until the core content works and the designer and developer can discuss the real product.

## Key Concepts
- **Epicenter**: The essential page unit that cannot be removed without changing the page’s purpose.
- **Core content**: The main information or action a customer visits the page to use.
- **Extremity**: A supporting part such as navigation, footer, sidebar, color, or logo.
- **Critical element**: A page part ranked by its value to the customer’s main task.
- **Frame-first model**: Building the page shape before adding its real content.
- **Page purpose**: The reason a customer needs the screen.
- **Design outward**: Add supporting parts after the core unit works.

## Mental Models
- **Cannot-live-without test**: Remove a page element mentally and see whether the page still serves its purpose.
- **Priority ladder**: Complete the first critical unit, then the second, then the third.
- **Content before frame**: Let the main content determine the screen instead of forcing content into leftover space.

## Anti-patterns
- **Frame-first design**: A finished shell can leave the core function with poor space and weak focus.
- **Extremity-first work**: Navigation, colors, and logos can consume time before the customer’s main need works.
- **Content-last insertion**: Pouring core functionality into leftover space reverses the correct priority.
- **Delayed design dialogue**: Waiting for the whole frame delays useful designer and developer decisions.

## Worked Example
For a blog-post page, the blog post itself is the epicenter. The sidebar categories, header navigation, footer, colors, logo, and comment form are not the first design task. Complete the post unit, then add the next most important part. This order keeps the page focused on the content that makes it a blog-post page.

## Key Takeaways
1. Identify the page’s cannot-live-without unit.
2. Design the core content before the frame.
3. Add elements by customer importance.
4. Delay navigation and decoration until the main task works.
5. Start designer and developer dialogue around the core unit.
